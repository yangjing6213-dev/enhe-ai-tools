# ZPAY 支付二维码显示修复

## 任务契约

- 目标：让支付页把 ZPAY 的 `qrcode` 支付链接显示成真正可扫描的二维码；对需要人工核对的既有支付尝试显示安全、清楚的提示。
- 范围：支付订单页、二维码显示组件、对应测试和依赖锁文件；只在隔离发布 worktree 修改。
- 不做：不读取或修改 `.env`、不查询或修改生产订单/支付状态、不调用真实支付、不伪造支付成功、不修改 ZPAY/微信商户后台配置。
- 已确认的外部问题：微信返回 `APPID_MCHID_NOT_MATCH`，需要把正确的微信应用 AppID 与商户号在 ZPAY/微信支付通道绑定；网站代码中没有可修正该绑定的 AppID。
- 安全边界：系统的 `ZPAY_PAYMENT_CREATION_RECONCILIATION_REQUIRED` 表示已有失败或结果不明的支付尝试。未经 ZPAY 查单确认及必要的通道处理，不清空、重用或重新发起该笔支付。

## 验收标准

1. 当网关只返回 `qrcode` 支付链接时，页面生成本地 SVG 二维码，不把整段链接当作二维码内容展示，也不把付款地址发送给外部二维码服务。
2. 网关提供二维码图片时继续显示该图片。
3. 需要支付核对时，页面说明暂不能重试以避免重复扣款，不向用户展示内部错误码或建议反复刷新。
4. 相关测试、类型检查、Lint、构建及发布门禁通过；检查本批次的 Git 差异和工作区。
5. 推送和部署仅发布本批次经验证的应用改动；部署后检查网站支付页不触发第三方二维码生成请求。

## 验证步骤

1. 先添加支付页行为回归测试并观察其在当前代码失败。
2. 实现本地 SVG 二维码与核对提示，再运行定向测试、`npm run typecheck`、`npm run lint`、`npm run build`。
3. 按项目现有发布脚本执行发布验证、推送和部署；核对线上页面及提交状态。
