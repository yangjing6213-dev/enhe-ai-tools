## 结论与检查范围

网站具备可抓取的正文、站点地图、多语言页面、资讯来源和产品信息等基础。当前最明确的问题是手机布局遮挡、公开封面被 robots 误挡、论坛缺少搜索信息、游客购买登录后丢失商品位置，以及图片和字体下载量偏大。本次先修复已确认且边界清楚的问题，其余按影响安排。

这是一份技术和使用体验检查，不是排名或流量增长证明。未访问 Search Console、Bing Webmaster、服务器蜘蛛日志和真实成交数据，因此不能给出真实收录率、搜索点击率、成交率或 AI 引用次数，也没有编造综合 SEO/GEO 分数。

实际检查：21 个 HTML 地址的搜索信息抽样；站点地图全量 URL 清单；robots.txt、llms.txt；10 类页面 × 手机/桌面共 20 个浏览器状态；6 类页面的单次资源体量采样；9 个公开地址各 3 次 HTTP 测量。浏览器审查拦截非 GET/HEAD 请求，没有登录、发帖、下单或付款。

## 下一批优化：按收益与风险排序

1. **工具目录封面减重（高优先）**：为公开封面设计受限尺寸、格式、字节数和缓存的图片代理/缩略图。不能直接删 `unoptimized`：当前内部接口返回签名 307，Next 内部优化器不跟随，会变成坏图。需要单独验证授权、重定向、缓存与坏图回退；不放开任意网络地址，不更改私有下载。
2. **字体分片/子集（高优先）**：当前完整中文字体约 2.41 MB，已有 swap 但仍需下载。分片后核验中英、用户名、论坛生僻字、数字和字体授权；不直接移除品牌字体或依赖收费服务。
3. **补齐转化入口统计（中优先）**：已有首页浏览、商品浏览、购买点击、开始结账、订单创建；新版首页和目录缺关键点击事件。复用现有访问统计机制记录入口→详情→登录→购买，不新增密码、邮箱或正文采集；需验证事件实际入库，不能把本次拦截到的准备发送当已入库。现有接口会保存登录用户 ID、IP 和浏览器信息，不能称为完全匿名。
4. **论坛内容发现（中优先）**：列表只取 30 条，更多帖子需要分页/加载入口。现有自动帖“相关阅读：/ai-news/...”是纯文本，应变成受控同站链接；补真实用户问题、可复现步骤、原始来源和回答，比堆砌关键词更重要。
5. **手机购买和注册路径实验（待业务确认）**：商品购买按钮在首屏下方；注册有 3 必填与 2 选填。可测试更清晰购买入口、选填资料后置，但不应直接改现有收集要求或再加遮挡屏幕的悬浮栏。
6. **辅助技术可用性（中优先）**：修目录链接名称、列表角色、浮动入口区域语义和资讯对比度，复查键盘/读屏；自动检查不能替代真人使用检查。

## 如何判断流量与转化是否真的改善

- Google Search Console：在“站点地图”检查 `https://www.enhe-tech.com.cn/sitemap.xml`，用“网址检查”检查论坛和 2–3 个商品规范网址，必要时请求重新编入索引。保留发布前后各 28 天页面/查询/设备/国家数据，比较曝光、点击和点击率；内容发布或渠道变化需要同时记录。
- Bing Webmaster：提交相同地图，检查抓取/索引错误。不要重复添加 www、无 www、尾斜杠不同版本。
- 站内 `/admin/seo-insights`：按来源观察落地→商品→购买→订单→支付确认；订单创建不等于营收，排除管理员/自动化访问。
- PageSpeed Insights / Search Console Core Web Vitals：查看真实手机用户 LCP、INP、CLS；样本不足时明确不足，不用单次本地测量冒充。
- GEO：固定一组用户真实问题，定期记录回答是否提及品牌、引用哪个原始页面、事实是否正确。保留日期、平台和证据，不自动批量发布低质量内容。
